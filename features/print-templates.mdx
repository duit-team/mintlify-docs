**Print Templates** define what a printed document looks like: customer receipts, kitchen tickets and kiosk pay-at-counter tickets. Create as many as you need and assign them to printers with [Routing Rules](/features/printers#routing-rules).

A template is plain text. **Tags** such as `<C>` format a line, and **values** such as `{ticket_number}` are replaced with real data when the ticket prints.

## The designer

Open **Setup & Config → Print Templates** and create or edit a template. The page has three parts:

| Part | What it does |
|------|--------------|
| **Editor** (left) | Colours tags and values as you type, suggests tags after `<` and values after `{`, and underlines mistakes (an unknown tag, a misspelled value, a row too wide for the paper). Press **Tab** or **Enter** to accept a suggestion. |
| **Preview** (middle) | Shows the receipt the way the POS will print it, using a sample ticket. Switch between **80 mm** (48 characters per line) and **58 mm** (32 characters per line). Click a line to jump to it in the editor. A blue bar on the left of a line means it prints as an image (large or accented text). |
| **Values and tags** (right) | A searchable list of everything you can use, with a sample of each value. Click a value to add it at your cursor. Click a tag to add a ready-made line. |

Above the editor, the **line toolbar** formats the line your cursor is on, so you never need to remember tag codes: **Align** (left, center, right, two columns), **Size**, **Style** (bold, underline) and **[ ]** (only print the line when its values are filled in). **Add block** inserts a ready-made section such as a header, items table or footer.

<Note>
  The preview uses a sample ticket, not one of your real orders. Always print one real ticket on your own printer before going live, because printers differ in fonts and paper.
</Note>

## Template types

| Type | Purpose | Printer device types |
|------|---------|----------------------|
| **Receipt** | Customer receipt printed after payment | POS, Kiosk |
| **Kitchen** | Order ticket for the kitchen or bar | KDS |
| **Pay at Counter** | Kiosk ticket with the order QR the cashier scans | Kiosk |

The type follows the **Device Type** you pick. Values that don't apply to a type (for example `{tendered}` on a kitchen ticket) are flagged in the editor.

## Template settings

| Field | Description |
|-------|-------------|
| **Name** and **Code** | Required. The code must be unique. |
| **Device Type** | Which app the template is for: POS, KDS or Kiosk. |
| **Status** | Inactive templates are never used. |
| **Default template** | Used when no routing rule picks a template. |
| **Item Name Size** | Normal, large (about 1.6×) or extra large (about 2.1×) item names. The name prints bigger on its own line, with quantity, price and total on a normal line below. It is a setting rather than a tag because `{ITEMS}` must stay alone on its line. |
| **User Confirmation** | Ask the cashier to confirm before this template prints. |
| **Logo** | The image printed where `<LOGO>` appears (after the template is created). |

## Formatting tags

Write one tag at the start of a line. Wrap a whole line in `[ ]` to skip it when any value inside is empty.

| Tag | Effect |
|-----|--------|
| `<L>` `<C>` `<R>` | Left, centered, right aligned line. `<C>-` prints a centered divider. |
| `<J>left\|right` | Two columns: text on the left, value on the right. |
| `<B>` `<UL>` `<INV>` | One bold, underlined or white-on-black line. |
| `<EB>` `<DB>` | Bold (or heavy bold) from this line until `<F>` or `<EC>`. |
| `<F>` / `<EC>` | Reset bold and size. `<F>-` prints a full-width divider, `<F>3` feeds three lines. |
| `<BIG>` `<HUGE>` | Large centered headline drawn as an image, safe on every printer. `<BIG>Total\|{total}` makes a big two-column row. |
| `<HR>` `<BR>` `<FEED>3` `<CUT>` | Divider, blank line, feed lines, cut the paper. |
| `<LOGO>` | Print the template's logo at the standard width. Use `<LOGO:S>`, `<LOGO:L>` or `<LOGO:XL>` for a smaller or larger logo (on 80 mm paper about 26%, 62% and 88% of the width; the standard is 38%). Small images are scaled up for the larger sizes, so use a sharp logo. |
| `<QR>text` `<BARCODE>text` | Print a QR code or Code 128 barcode. |
| `<ITEM_HEADER>` | Header row for the items table. |
| `<OPENDRAWER>` | Open the cash drawer. |

The full, always-current list is in the **Values and tags** panel.

### Sizes (syntax v2)

Put two digits after the letter: the first is the **width**, the second the **height**. `0` is normal, `1` is double, `2` is triple.

| Tag | Result |
|-----|--------|
| `<C11>{location_name}` | Centered, double width and double height |
| `<J10>Total:\|{total}` | Two-column row at double width |
| `<L01>Table {table_number}` | Left, normal width, double height |
| `<C22>` | Centered, triple size |

Larger characters leave fewer columns on the line: on 80 mm paper a double-width line holds 24 characters instead of 48, and the preview warns when a row won't fit. On printers where large native text is unreliable (iMin built-in printers) and for accented text, the POS draws the line as an image instead, so it looks the same.

<Warning>
  **Syntax versions.** Templates created before this designer use **syntax v1**, where `<L11>`, `<C22>`, `<J10>` and similar tags only print **bold**, not larger. They keep printing exactly as before. To use real sizes, click **Upgrade to v2** in the designer. The dialog tells you how many lines will get bigger; check the preview, then save. New templates start on v2.
</Warning>

## Values

Values are written in single braces: `{ticket_number}`. They print the data of the ticket; an unknown value stays as typed, which the editor underlines.

| Group | Examples |
|-------|----------|
| Ticket | `{location_name}` `{ticket_number}` `{queue_number}` `{order_mode}` `{table_number}` `{employee_name}` `{timestamp}` `{TICKETNOTE}` `{ticket_tag}` |
| Customer | `{customer_name}` `{customer_phone}` |
| Totals | `{subtotal}` `{total}` `{item_count}` `{total_qty}` `{total_in_words}` `{currency_symbol}` |
| Payment | `{payment_method}` `{tendered}` `{change}` |
| QR codes | `{einvoice_qr_url}` `{receipt_qr_url}` `{pay_at_counter_qr_data}` |
| Labels | `{label_total}` `{label_thank_you}` … translated to the POS **Printer Language** |

### Repeating blocks

A block on a line of its own prints one row for every item, charge or payment:

| Block | Prints |
|-------|--------|
| `{ITEMS}` | Every item (name, quantity, price, total) with its modifiers |
| `{CHARGES}` | Every tax, service charge and discount |
| `{PAYMENTS}` | Every payment with its reference |

### Added automatically

To keep tickets complete, the POS adds a few lines when your template leaves them out: the ticket note and tag, the item and quantity count above the subtotal, and the split-bill summary under the total. On a **Pay at Counter** ticket the order QR is always added. Use the value in your own layout to place it where you want it.

## Example

```
<LOGO>
<C22>{location_name}
<C>{timestamp}
<F>-
<J>{label_ticket}|{ticket_number}
[<J>{label_table}|{table_number}]
<F>-
<ITEM_HEADER>
<F>-
{ITEMS}
<F>-
{CHARGES}
<J11>{label_total}|{currency_symbol}{total}
{PAYMENTS}
<C>{label_thank_you}
```

## Create a template

<Steps>
  <Step title="Open Print Templates">
    Go to **Setup & Config → Print Templates** and click **New**.
  </Step>
  <Step title="Name it and choose the device">
    Enter a **Name** and a unique **Code**, then pick the **Device Type**.
  </Step>
  <Step title="Design the layout">
    Use **Add block** for a starting point, then edit. Watch the preview, fix anything the editor underlines, and check both paper widths if you use both.
  </Step>
  <Step title="Save">
    Click **Create**. Upload a logo afterwards if the template uses `<LOGO>`.
  </Step>
</Steps>

## Assign to printers

Go to **Setup & Config → Printers** and set a template as the printer's default, or as the override of a routing rule. If a rule has no override, the printer's default is used; if that is empty too, the template marked **Default template** is used.

<Warning>
  Deleting a template that a printer or rule uses makes them fall back to the next default. Check your printers after deleting one.
</Warning>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Why does my size tag print bold instead of larger?">
    The template is still on syntax v1. Click **Upgrade to v2** in the designer (the badge above the editor), review the preview and save.
  </Accordion>
  <Accordion title="Why are some preview lines marked with a blue bar?">
    They print as an image: `<BIG>`/`<HUGE>` headlines, large sizes on printers that can't do native large text, and any line with accented characters (Vietnamese, for example). They look right on every printer, but cannot use the printer's own font.
  </Accordion>
  <Accordion title="Why does my logo print as a black block?">
    Colourful logos are converted to black-and-white dots. Dark marks on a coloured background print as a solid mark over a grey dot pattern. For the sharpest result, use a high-contrast logo (dark on white). Use `<LOGO:L>` for a bigger one, or put the business name in large text instead, for example `<C22>{location_name}`.
  </Accordion>
  <Accordion title="A value prints as {something} on paper">
    The name doesn't exist (check the spelling; the editor underlines it) or it isn't available for this template type. Pick it from the **Values** panel instead of typing it.
  </Accordion>
  <Accordion title="How do I hide a line when a value is empty?">
    Wrap the whole line in square brackets, for example `[<L>Customer: {customer_name}]`, or click the **[ ]** button on the line toolbar.
  </Accordion>
  <Accordion title="Does the preview match my printer exactly?">
    Line breaks, columns, sizes and what prints as an image match the POS. The font itself is your printer's, so spacing of individual letters can differ slightly. Print one real ticket to confirm.
  </Accordion>
</AccordionGroup>
